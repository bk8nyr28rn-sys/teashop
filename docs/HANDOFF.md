# 交接说明（给接手调试的工程师或 AI 代理）

> 更新：2026-11-15。先读这一份，再读 `README.md`、`docs/ART_SPEC.md`、`docs/DESIGN_v2.1.md`。
> 冲突时的优先级：**本文件的“不能破坏的规则” > 代码里的测试 > `docs/DESIGN_v2.1.md`**（方案文档写在原型之前，有些细节已被后续决定改掉，见第 6 节）。

## 1. 这是什么

一个竖屏小游戏的**逻辑核心 + 数值模拟器 + 网页可玩原型**。玩法：Q 版修仙小院守宅打鬼 × 玩家之间的红线关系 × 修仙家族。目标平台是微信小游戏（Cocos Creator 3 + TypeScript），现在还没有 Cocos 工程和服务器。

设计北极星：**始终以玩得爽为目的**；画面以 Q 版修仙为主，**戏曲只做点缀**。

## 2. 跑起来

需要 Node 22（20 以上应该也行）。

```bash
npm ci               # 装依赖（只有开发依赖：typescript、vitest、tsx、esbuild、@types/node）
npm test             # 单元测试，当前 84 个全部通过
npm run typecheck    # 两次类型检查：核心用不含 DOM 和 Node 的配置单独检查
npm run sim          # 数值模拟：6 类玩家 × 200 人 × 30 天，约 1 秒
npm run sim -- --days 120 --players 300 --set big.strandsPerStone=0.04
npm run build:web    # 打包原型：dist/web/teashop.html（单文件，浏览器直接打开）
```

压缩包里的 `prototype/teashop.html` 就是打包好的原型，手机或电脑浏览器直接打开即可。

## 3. 目录与架构

```
src/core/    逻辑核心：纯 TypeScript，不能用 window / document / process / 任何 Node 模块
             （tsconfig.json 用 "lib": ["ES2020"], "types": [] 强制检查）。以后原样放进 Cocos。
  config.ts    所有数值（唯一的调参入口），每项有中文注释
  world.ts     世界、家族、时间、闭关、保护期、updateProfile
  threads.ts   红线：牵线、互动、大互动、吃醋、争执与和好、剪线、复合、拉黑、冷落、情丝去向
  grudge.ts    怨丝池与每日上限
  defense.ts   守宅：两种鬼、砸门结算、感化、门被砸破、劫后余生、阵法、炼丹、渡劫
  family.ts    族人与嫡传
  rivals.ts    NPC 情敌与真人抢亲
  tick.ts      每个游戏小时推进一次（advanceHour）
  save.ts      存档读档（确定性：读档后继续玩和不存档完全一样）
  messages.ts  事件 → 玩家看得懂的一句话
src/sim/     模拟器（agents.ts 玩家行为假设、simulate.ts 统计、cli.ts 命令行）
src/web/     网页原型（只是界面壳）：game.ts 控制层、ui.ts 各页面、art.ts 占位美术、main.ts、page.html 样式
test/        core.test.ts（规则）、save.test.ts（存档与提示）
docs/        本文件、美术规格、方案文档、参考截图
design/      设计稿画布的源文件（.dc.html 是 HTML + 一段组件脚本，要在在线画布里才能渲染；看样子请用 docs/art/screens 的截图）
             ⚠️ 画布是 11 月 14 日的旧稿，形象里还有已删掉的戏曲款（翎子、凤冠、行当）。以 ART_SPEC.md 和截图为准
```

数据流：界面层只调用 `src/core/index.ts` 导出的函数，规则引擎通过 `world.listener` 发事件（`GameEvent`），界面层把事件变成弹字和动画。**不要在界面层写规则**。

代码注释里的 `#N` 对应方案文档“决定记录”的编号（#1–#21 在 v2，#22–#32 在 v2.1 变更）。

## 4. 不能破坏的规则（改代码前先对照）

| 冷落只算“搭档发来的互动超过几天没回”，**不在线本身不算** | #5 |
| 闭关（含未成年禁玩时段的自动闭关）只负责保护：不变淡、不生怨、冷落不计时、鬼不来；**族人照常结**；未成年的自动闭关不占额度 | #5 #21 |
| 离线期间最多被砸破一次（劫后余生按“行动次数”倒数，离线不行动） | #8 #11 |

| 怨丝变回情丝的比例必须 **< 1:1**（打散 10–30%、感化 50%、破镜重圆 20%）；吵架后和好、剪线后复合都必须**净亏**，否则会被刷 | #14 #28 #29 |
| 每日新生怨丝有上限，超出直接散掉 | #12 |

## 5. 数值校准目标（改数值后用模拟器确认）

当前默认值的模拟结果（120–130 天，每类 300 人）：

| 指标（好友一对一，中位数） | 当前 | 目标 |
| --- | --- | --- |
| 到“知己” | 第 1.9 天 | 第 1–2 天 |
| 第一位族人 | 第 2.5 天 | 第 2–3 天 |
| 结出嫡传 | 第 16 天 | 第 2–4 周 |
| 金缕 | 第 90.5 天 | 约 90 天（产品定的“约 3 个月”） |
| 砸破 / 周 | 约 0.54 | 有压力但不劝退（约 0.4–0.9） |

其他必须保持的相对关系：
- 多对象（和一对一同样投入）**更难、更慢，但不能被压死**：砸破次数更多、嫡传更慢，族人不能少于一对一太多
- 忙碌玩家（隔天上线）不能掉队太多：90 天单线浓度不低于一对一的约 80%
- 模拟报告里“单次离线输 ≥2 次”永远是 0
- 独自玩（NPC 线）比好友慢约一倍是**有意的**（真人线两个人投入），不要“修”

经验教训（之前踩过的坑）：
1. 调一个数值会连锁影响别处。例：族人来得早 → 门更厚 → 丢的灵石少 → 能押的多 → 金缕变快。每次改完跑全套模拟
2. 任何“亏了再赚回来还多一点”的机制都会被刷（吵架刷浓度、剪线复合刷浓度都出现过）
3. 给“追赶机制”加门槛，往往正好挡住最需要它的人（大互动曾经要求“知己”才能做，结果忙碌和未成年玩家被锁在外面）

## 6. 方案文档里已经过时的地方

`docs/DESIGN_v2.1.md` 写于网页原型之前，以下以代码为准：

- **画面方向**：文档里戏曲元素很重（戏台、剧种主题表）。现在的方向是“Q 版修仙为主，戏曲只做点缀”，见 `docs/ART_SPEC.md` 第 0 节
- **大互动**：文档叫“大互动”或“唱一出”，现在叫“**结伴历练**”；兑换比例从 0.05 调到 **0.038**
- **新手期**（文档里没有）：保护期内的练手小鬼；相识阶段情丝 ×8；前两位族人只要平时 3% 和 15% 的进度
- **戏曲**：文档里的行当、戏曲头饰都已经从形象里拿掉；行当改成“道途”（剑修、丹修等，只是标签）
- **首页是家族大院地图**（文档里没有）：鬼在院外游荡、从三个院门进来砸你家的门；族人住小屋、搭档住隔壁。规则不变，只是表现层
- **点鬼**只是手感（火花 + “啪！”），不改砸门结果。要让它影响结果是规则改动，先问产品负责人
- **服装风格**：`Appearance.outfit`（仙袍 / 短褂 / 卫衣），玩家自选，画风不定死
- **形象**（文档里没有）：`House.appearance` 和 `House.gender`，玩家自己捏，见 `ART_SPEC.md` 第 4 节
