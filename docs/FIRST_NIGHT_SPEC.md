## 为什么要改

你在 `docs/STAGE1_REPORT.md` 里发现：带路的第一晚只能用剑，可飞鬼（剑够不着）和隐身鬼（剑看不见）照样会来。
产品负责人用规则核心试算过：第一晚只用剑，每秒 2 下只守住 15%，每秒 4 下也只守住 34%。第一次玩的人大多会被砸破门，还要丢三成钱。

产品负责人 11-21 定了：**鬼跟着工具一起来**（已写进 `docs/ROADMAP.md` 已定表「鬼跟着工具一起来」那一行）。

## 要做什么

**1. 手里只有剑的晚上，只来普通鬼。**
- 条件和样机里限制手持物的条件一样：`!Guidance.open(2)`（也就是没开「全部开放」，而且是这一世的第 1 天）。回自家投胎的第一天也算。
- 这一晚五波都只来普通鬼（`evil`）；飞、隐、甲都是 0。
- 其他晚上、开了「全部开放」的玩家、护家神那一晚：**一个数都不改**。

**2. 普通鬼多加几只，让这一晚有点紧张。**
只来普通鬼时，门几乎不掉血（试算：每秒 2 下守住 100%，门剩 99%），太轻松了。只给这一晚加普通鬼的数量，调到下面这个范围。机器人用报告里「分天开放首夜只用剑」那种打法，每格 200 局：

| 每秒点几下 | 守住 | 守住时门剩多少 |
| --- | --- | --- |
| 1.5 下 | 至少 90% | 不要求 |
| 2 下 | 至少 95% | 平均 70%–90% |
| 4 下 | 100% | 不要求 |

机器人每下都点得准，真人会点空，所以要留余量：宁可偏简单，不要偏难。

**3. 样机和规则核心一起改。**
- 规则核心里给守夜加一个开关（名字你定，例如「工具开放了没有」），新加的数字放进 `NIGHT.counts` 这类配置里，不要写死在函数里。
- 改完 `npm run balance:night -- --compare-core` 还要逐局对得上，并且把第一晚这一行也加进对账。

## 验收

- 单元测试：带路第一晚的五波里没有飞、隐、甲；开了「全部开放」的第一晚和改之前一模一样；第 2 晚以后和改之前一模一样
- 浏览器测试：带路的第一晚真的只来普通鬼；原有的带路测试照样全过
- `npm run typecheck`、`npm test`、`npm run sync:draw -- --check`、`npm run test:proto` 全绿
- `npm run balance:loop`：除了第一晚那几行，其他格子的数字和 `docs/STAGE1_REPORT.md` 完全一样
