# 第二阶段：家的存档、两个口袋、一晚只结算一次（给 Codex）

> 2026-11-21。等「第一晚只来普通鬼」（`docs/FIRST_NIGHT_SPEC.md`）验收以后再做这个。
> 先读 `docs/ROADMAP.md` 已定表里「家里的东西归谁」「两个口袋」「两个口袋的细则」「没有后人时」这几行，再读 `docs/SESSION_REVIEW.md` 最后那张表的第 2 行。做完停下来汇报。

## 这次要做成什么

一句话：**东西归家还是归人，存档里分得清清楚楚；每一晚只结算一次。**

现在样机里只有一堆钱（`G.money`）和一个仓库（`G.store`），全都挂在这一世的人身上。这次要把它拆成「家」和「人」两份，并把产品负责人定好的口袋规则做进去。

## 产品负责人定好的规则（11-20、11-21）

| 规则 | 说明 |
| --- | --- |
| 东西归家 | 钱箱、仓库、院子、门、机关、宝物架、祠堂归「家」，不归哪一个人 |
| 两个口袋 | **钱箱**（家的）：只能花在家上。**钱袋**（人的）：自己挣的钱 |
| ① 谁背回来就是谁的 | 野外背回家的东西（宝物也一样）先是**自己的**；卖了钱进钱袋。自己「放进仓库 / 摆上宝物架」才归家；家里的东西卖了，钱进钱箱 |
| ② 门破了随机抢 | 亲手守门破了：钱袋随机抢走 **2–4 成**，钱箱锁着只抢 **0–2 成**，宝物架上照旧随机丢一件。抢多少**开打前就定好**（用这一晚的种子），刷新、重开都不重抽 |
| ③ 看东西最后落在哪 | 花完东西**留在家里**的（换门、装机关、扩院子、装饰、收徒弟）：钱箱、钱袋都能付。东西**到了某个人手里**的（送礼物、买兵器、送邻居钱和东西）：只能用钱袋和自己的东西 |
| 不能取出来 | 钱袋可以放进钱箱；**钱箱的钱不能取回钱袋** |
| 老死时 | 钱袋里剩的钱进钱箱，自己的东西进仓库 |
| 回自家投胎 | 钱箱、仓库、院子、机关、宝物、画像一文一件不少。新的一世钱袋从 0 开始 |
| 没有后人时 | 宅子不消失：投到别人家以后，原来那户的存档还在（以后要长草、门变旧；这次只要把记录留住，加一个标记） |

## 要做什么

### 1. 存档分成「家」和「人」

- 每户人家有稳定的 `houseId`，每一世的人有 `lifeId`。家名可以重名，不能靠名字认家。
- 存档里可以同时有好几户人家：投到别人家以后，原来那户（钱箱、仓库、院子、机关、宝物、画像）原样留着，不会被同姓的另一户合并或覆盖。
- 画像在老死时按 `lifeId` 挂进原来那户的祠堂，**只挂一次**：不管之后投胎去哪，不重复、不漏。
- 守夜的结算回执（A1 做的）改成按 `houseId + nightId` 记在家上；`nightId` 跨世连续，不会因为换了一世从头数。
- 存档版本升到 `v: 4`。账号那一份（攒天、设置、带路记录、捏的脸）和以前一样跨世保留。

### 2. 旧存档迁移

- v2 / v3 的旧档读进来：**旧的钱进钱箱，旧仓库的货进家里的仓库**（以前这些就是家里的），钱袋从 0 开始。门、机关、宝物、画像、院里的石头原样搬过去。
- 迁移两次和迁移一次结果完全一样。
- 已经被扣过两次、又没有回执的旧档，没法还原，照现有余额迁移就行。

### 3. 两个口袋做进样机

现在会动钱和货的地方都要按上面的规则改（你上次报告里列过：`openMarket`、`sellGoods`、`sellAll`、卖宝物、`openBuild`、`takeDisciple`、`openFriends` 的送钱送货、`arriveHome`、河边背柴回家、`heal`、`endNight`、`reborn`）。几个要定的细节，照这样做：

- **到家**：背回来的东西进「自己的」那份，不再自动进仓库。
- **卖货**：集市里分「我的」和「家里的」两块，卖哪块钱进哪个口袋。
- **放进家里**：能把自己的东西一键全放进仓库，能把钱袋里的钱放进钱箱。
- **买家里的东西**（门、机关、收徒弟）：先用钱箱，不够再用钱袋，提示里写清楚各付了多少。
- **送邻居**：送钱只能用钱袋；送东西只能送自己的。
- **疗伤**：先用自己的草药，没有再用仓库里的（家里人受伤用家里的药，不算掏空）。
- **守夜捡到的纸钱**：进守夜的人的钱袋。
- **当厉鬼抢到的东西**：照旧带进下一世；钱进下一世的钱袋，宝物算自己的。
- **新的人家**（投到别人家、第一世的林家）：起始的钱进那户的钱箱。

**界面要求**（「减字」的原则照旧）：
- **第一天不用懂两个口袋也能玩通**：砍柴 → 回家 → 卖掉 → 换木门，照样一路走通（钱箱 20 文 + 钱袋卖柴的钱，够了就能换）。
- 两个口袋放进带路：在第 3 天开放「家和祠堂」时，用一句「今天的念头」讲清楚，例如「钱放进钱箱更安全，但只能花在家上。」措辞你定，一句话。
- 顶上的钱怎么显示你定（两个数，或者一个总数点开看），要在 390 × 844 和 320 × 640 都放得下。

### 4. 一晚只结算一次（门破了怎么抢）

- 这一晚开打时，就用这一晚的种子定好：门破了的话，钱袋抢几成（2–4 成里抽）、钱箱抢几成（0–2 成里抽）、丢哪件宝物。存在这一晚的状态里。
- 结算时按存下的比例算，向下取整。钱很少时允许抢 0 文。
- 刷新、两个标签页、旧标签页晚一点才结束：都只入账一次（A1 的测试保留，改成新存档也要过）。
- 战报写清楚：「鬼翻到你的钱袋，抢走 31 文；撬开钱箱，抢走 8 文；宝物架上的古玉没了。」

### 5. 规则写一份，页面和核心共用

上次的报告说得对：页面和核心各写一份，最容易只测了一份、玩家走的是另一份。
**建议**：家和人的存档、两个口袋的收支、迁移、一晚的结算，只在 `src/core/loop/` 里写一份，用 esbuild 打成 `assets/loop-core.js` 给样机页面用（加一个 `--check`，像 `sync:draw` 那样防止忘了重新打包；离线副本 `prototype/` 也要能用）。守夜的打斗过程这次**不用**改成调用核心，页面照旧自己打，只把结果交给核心结算。
如果你判断打包这一步风险太大，可以不做，但要在汇报里说明理由，并用对账测试保证两份结果一致。

## 验收

**单元测试**（进 `npm test`）：
- 口袋规则每条至少一个测试：①卖自己的进钱袋、卖家里的进钱箱；放进仓库 / 钱箱；钱箱取不出来；③家里的东西两边都能付、先扣钱箱；个人的东西只能用钱袋；送邻居只能用自己的
- 老死：钱袋进钱箱、自己的东西进仓库；画像只挂一次
- 门破了：同一个种子抢的比例一样；比例永远在 2–4 成和 0–2 成之间；刷新不重抽；少量钱时不出现负数
- 迁移：v2、v3 各一个样本，迁移两次结果一样
- 换后人：选第二个后人投回自家，那户的钱箱、仓库、院子、机关、画像都对；投到别人家，原来那户的记录还在，不会和同姓的另一户合并

**浏览器测试**：
- 带路第一天：砍柴 → 回家 → 卖 → 换木门，一路走通
- 门破了在结算页刷新（普通一晚、最后一晚、护家神那一晚）：只扣一次，战报一样
- 第 3 天的念头讲到了钱箱
- 两种屏幕尺寸截图，没有横向滚动、没有控制台报错

**照旧全绿**：`npm run typecheck`、`npm test`、`npm run sync:draw -- --check`、`npm run test:proto`；`npm run balance:night -- --compare-core` 还要逐局对得上（这次不改守夜难度）。
