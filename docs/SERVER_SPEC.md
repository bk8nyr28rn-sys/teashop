# 服务器设计：真人版第一版

> 2026-11-28 初稿。前六节给产品负责人看，第七节起给 Codex 看。
> 先读 `docs/ROADMAP.md`（已定的规则）和 `docs/HANDOFF.md`。这份只讲「搬上服务器以后怎么算、怎么存」，**尽量不改玩法和数值**；因为有了真人不得不改的地方，都标了「⚠️ 要改」。
> 标「⏳ 待定」的地方要产品负责人拍板，现在按「建议」写。

## 一、一句话

**手机只告诉服务器「我做了什么」，服务器用同一套规则核心算结果、记账。** 第一版真人之间全是异步的（不用约时间），所以用**微信云开发**就够了。

为什么现在可以开始：第一到第六阶段已经把规则搬进了 `src/core/loop/`。它是纯 TypeScript，不碰画面，随机数从外面传进去，守夜和当厉鬼都按固定的步子走。所以**同一份代码**能放三个地方跑：手机上（Cocos 正式版也是 TypeScript）、服务器上、模拟器里。服务器拿到玩家的操作记录，自己重放一遍，就知道结果是真是假。

## 二、家族、房、人（11-28 定）

多人版不是「一家一座房子」，而是三层。玩家住哪、和谁住，自己选：

```
林家（家族）
├─ 祠堂：全族共用，祖宗画像都挂在这
├─ 林大的房：林大 + 伴侣（伴侣可以搬来，也可以不搬）
├─ 林小的房：林大的孩子长大了，自立门户
└─ 老宅：没人住了，东西还在
```

| 层 | 是什么 | 有什么 |
| --- | --- | --- |
| **家族** | 一个姓的一大家子，靠爹妈、红线、师徒连起来 | 族名、**祠堂**（祖宗画像全挂这）、族谱。投胎时「回自己家」就是回自己家族 |
| **房** | 一座宅子，一个人住、几个人住都行 | 门、机关、钱箱、仓库、宝物架、院子、灶、装饰 |
| **人** | 一辈子 | 天数、年纪、钱袋、背包、交情 |

- **住哪随你**：成年以后可以一直住在爹妈的房里，也可以**自立门户**，在族里再起一座房。成亲不用搬：各住各的、搬过去、一起起新房都行，以后也能改。搬进别人的房要那座房里的人答应，搬出来不用
- 以前定的「家里的东西归家」，在多人版里是：门、钱箱、宝物这些**归房**；祠堂**归家族**
- 人老死：钱袋进自己住的那座房的钱箱（照两个口袋细则 ④）
- 一座房里住着好几个真人时，夜里**谁输谁疼**（第四节第 1 条）
- 单机样机里一个家族只有一座房，**样机不用改**

## 三、真人之间的事，第一版怎么做

全部异步。下面按「先有哪个、后面的才能做」排：

| # | 事情 | 第一版怎么做 |
| --- | --- | --- |
| 1 | **家族、房、人** | 见第二节。房的东西存一份，住在里面的人都能用；每个人有自己的天数、年纪、钱袋、背包 |
| 2 | **真人投胎来当孩子** | 爹妈红线到知己、或者收了徒弟，他们住的那座房就有一个「空位」。回自己家投胎 = 回自己家族，族里哪座房有空位都能挑。死了的老玩家在奈何桥挑人家、新玩家随机分，都只从有空位的真人的房里挑。孩子一来就算出生，爹妈下次上线看到「孩子出生了：某某投胎来了」。⏳ 空位等多久没人来就让 NPC 孩子先占着，见第四节第 4 条 |
| 3 | **真人红线** | 「找有缘人」的候选里有真人（成年、没成家、天数差不多）。你牵线，对方下次上线答应了才算。红线两个人共用一个数，谁陪伴都涨。⚠️ 要改：现在每过一个游戏天早上涨一下，两个真人各过各的天就会涨两份，所以改成**一个现实日只涨一次**。没有真人愿意的，照旧有 NPC 伴侣。成亲以后住哪随你（11-28 定，见第二节） |
| 4 | **真人厉鬼、护家神** | 老死的玩家选当厉鬼，服务器挑一座真人的房（不是自己家族的、不是交情深的、不在保护期、强弱相当），他打的是那座房**当时的门和机关**。打完服务器重放核对，结果记到那座房的战报里，主人上线时祖宗告诉他「昨夜某某的厉鬼来砸过门」。一座房一个现实日最多来一个厉鬼。⏳ 能不能抢走宝物，见第四节第 3 条。护家神是回自己家族的一座房守一夜 |
| 5 | **结伴、驰援借好友** | 借的是好友这个人的「快照」（长相、强弱、交情），由电脑操控。不用好友在线，也不用他同意；用一次给他也加一点交情，他上线时看到「你帮某某守了一夜」。⏳ 同族的人也能这样借来帮忙，见第四节第 10 条 |
| 6 | **好友投奔** | 你发分享链接，好友点开就生在你的房里（占一个空位）或者拜你为师 |
| 7 | **族人之间留东西、留话** | 东西：住一座房的本来就共用；不住一起的，能把东西送进对方房里的仓库。留话：写在祠堂里，过微信的内容安全检查 |
| 8 | 野外掉的包别人能捡 | **第一版先不做**，掉的包只有自己能回去捡。等有了「多人地图」再做 |

## 四、要产品负责人定的

| # | 问题 | 建议 | 为什么 |
| --- | --- | --- | --- |
| 1 | **一座房里住着几个真人时，夜里怎么算？输了谁疼？** | ✅ **11-28 定：谁输谁疼**。各守各的夜，同一座房里的人守的是同一扇门。每个人按自己的天数过夜，用的是房里的门和机关。门破了：**自己的钱袋**照常被抢两到四成；**钱箱和宝物**只有房里就住着你一个真人时才按亲手守的规矩丢；房里还住着别的真人时，按交给机关的上限丢（钱箱最多 20 文，不丢宝物） | 孩子是陌生人投胎来的。照现在的规矩，他亲手守输一夜，就能让全家丢两成钱箱外加一件传家宝，故意输也行，等于给了陌生人一把砸自家的锤子。改成「人多时输了只疼自己」，输的痛还在，但坑不了家人 |
| 2 | **成亲以后住谁家？** | ✅ **11-28 定：不定死，玩家自己选**。改成「家族 → 房 → 人」三层（第二节），各住各的、搬过去、一起起新房都行 | 自由度拉到最高 |
| 3 | ⏳ **真人厉鬼能不能抢走不在线人家的宝物？** | **不能**。已定的规矩是「不在线最多丢一点钱，不丢宝物」，而真人厉鬼来的时候主人一定不在线。所以被砸的那座房照旧最多丢 20 文；厉鬼自己照常拿到战利品（带进下一世的钱和一件宝物，是新生成的，不是从那座房拿的） | 不在线也能安心，这条是 11-20 定的，不能因为真人厉鬼破掉 |
| 4 | ⏳ **空位等真人多久？** | 等 **1 个现实日**。没人来就先让 NPC 孩子占着（和现在样机一样能玩）。空位一直开着，真人来了就再生一个，最多两个孩子的上限照旧 | 爹妈一辈子只有 1–2 周，等太久就错过了养孩子的那几天 |
| 5 | 用微信云开发还是自己租服务器？ | **微信云开发**（我先按这个写） | 登录不用自己做（直接拿到玩家身份），不用自己运维，第一版全是异步，够用。规则核心不绑死平台，以后要换能换 |
| 6 | 现实里的「一天」从几点开始算？ | **北京时间早上 5 点**（我先按这个写） | 「打到一半离开，当天回来接着打，隔天回来就当交给机关」。要是 0 点换天，23:50 开打、00:10 回来就变成隔天了 |
| 7 | ⏳ **自立门户时，爹妈给多少？** | 照「**分家**」来：自立门户的人从原来那座房的钱箱分走一笔起家，房里其他真人答应才行 | 新房一文没有、门是破的，第一晚就会被砸 |
| 8 | ⏳ **起一座新房要不要花钱？** | 要，起家的钱先花在这上面，起出来是小院、木门 | 不花钱就能无限开房，家族里会冒出一堆空房 |
| 9 | ⏳ **爹妈不是一个家族时，孩子算哪族？** | 算生他的那座房所在的家族 | 最简单，和住哪连在一起 |
| 10 | ⏳ **族里的房能不能互相帮着守门？** | 能。同族的人不用攒交情，就能借来驰援，每晚一次 | 各住各的以后，夜里一个人守门太孤单；家族要有一起扛的感觉 |

## 五、谁说了算

| 东西 | 谁算 | 说明 |
| --- | --- | --- |
| 今天几号、给不给攒天 | 服务器 | 用北京时间 5 点换天，不看手机的钟 |
| 钱、货、宝物、门、机关、院子 | 服务器 | 手机只发「卖 3 件柴」，服务器自己按当天的价算钱 |
| 白天出门（走路、采集、打野兽） | 服务器核对 | 手机先算、马上给画面；服务器按同样的种子重算一遍，对不上以服务器为准 |
| 守夜、当厉鬼的打斗 | 服务器重放 | 手机打，打完把**操作记录**交上去；服务器用同一个种子、同一版规则重放，结果以重放为准 |
| 门破了抢多少、宝物丢哪件 | 服务器 | **开打前**就定好（已定的规矩），种子只在服务器 |
| 投胎的三户候选 | 服务器 | 抽出来就存下，刷新不重抽 |
| 长相、表情、手绘 | 手机 | 外观不影响结果；名字和手绘要过内容安全检查 |
| 画面、声音、念头、祖宗说话 | 手机 | 不上服务器 |

## 六、钱（服务器的费用）

- 云开发按「套餐 + 超出部分按量」收费，2026 年改过一次价，具体数字**以官方价格页为准**。2026 年微信有小程序成长计划，新开发者能免费用一段时间的个人版。
- 我们能控制的是**调用次数**：手机把一串操作攒起来，在「回家、去集市、修院子、天黑、天亮」这些节点一次交上去，不是每点一下都调一次。估计一个玩家每个现实日 20–30 次调用。
- 守夜重放是纯计算、不画画面，一夜几千步，几十毫秒就算完。

## 七、给 Codex：数据怎么存

现在的存档（`src/core/loop/household.ts` 的 V4：`account / person / houses`）已经按「账号、人、房」分好了。服务器照这个拆成几个集合（collection），再多一层家族（`clans`）：

| 集合 | 一条是什么 | 主要字段 | 从 V4 哪里来 |
| --- | --- | --- | --- |
| `accounts` | 一个微信账号 | `_id = openid`、攒天（`bankedDays`、`lastGrantDate`）、设置（`skipAfterlife`、`guideOff`、`guideSeen`）、`history`、`currentLifeId`、`friends`（对别的账号的交情） | `account` |
| `clans` | 一个家族 | `clanId`、族名、`ancestors`（祠堂画像，从房里挪到这）、`houses`（族里的房）、族谱（谁是谁的爹妈、伴侣、师父）、留话 | 新。单机存档转过来时，一个家族只有一座房 |
| `lives` | 一个人的一辈子 | `lifeId`、`accountId`、`clanId`、`houseId`（现在住哪座房）、`lifeNo`、名字、捏人码、`day`、`time`、`purse`、`goods`、`bag`、`personalTreasures`、红线（`bondId`）、爹妈和孩子（`lifeId` 或 NPC）、`rngState`、`status`（活着 / 当鬼 / 走完） | `person` |
| `houses` | 一座房 | `houseId`、`clanId`、`name`、`chest`、`store`、`door`、`traps`、`treasures`、院子（`yardLevel`、`decor`、`plaque`、`stoves`）、`residents`（住在这的活人 `lifeId`）、`cradles`（空位）、保护期、`abandoned`、**`rev`（版本号）** | `houses[id]` |
| `bonds` | 一条红线 | 两个 `lifeId`（或一边是 NPC）、`love`、`lastDawnDate`。住哪不记在这，各看各的 `houseId` | 现在在 `person` 里 |
| `nights` | 一个人的一夜 | `lifeId`、`day`、`mode`（亲手 / 交给机关 / 不在线）、`seed`、开打前定好的抢夺计划、`ruleVersion`、操作记录、战报 | `nightPlan`、`receipts` |
| `raids` | 一次真人厉鬼 | 厉鬼的 `lifeId`、目标 `houseId`、`seed`、目标房当时的门和机关快照、操作记录、结果 | 新 |
| `rebirths` | 一次投胎的候选 | `lifeId`、因果分各项、三户候选（存下来，刷新不重抽） | 新 |
| `inbox` | 回来时要告诉玩家的事 | 对象（家族 / 房 / 人）、种类（生孩子、厉鬼来过、被借去帮忙、红线答应了、族人自立门户、有人要搬进来）、时间、已读 | `absencePeriods`、`absenceReadThrough` |
| `ledger` | 一笔账 | `opId`、谁、哪座房、钱箱和钱袋各变多少、为什么 | 新。只追加，客服查账、回滚用 |

规则：

- **ID 都由服务器发**，不再用数组下标指东西（宝物、后人、候选家都要有自己的 `id`）。`SESSION_REVIEW.md` 第五节列过这个问题
- 捏人码、手绘图案存进云存储，`lives` 里只放引用
- 祠堂画像：人死的时候把捏人码和名字**复制一份**进 `clans.ancestors`，以后这个账号改脸不影响祖宗

## 八、给 Codex：一次操作怎么走

```
手机：按规则核心先算 → 马上给画面 → 攒成一批 {opId, lifeId, baseRev, ops[]}
   ↓ 在节点上提交（回家、去集市、修院子、天黑、天亮、关游戏前）
服务器：
  1. 看 opId 处理过没有 → 处理过就直接回上次的结果（网络重试不会重复扣钱）
  2. 读出 life 和 house，用服务器存的随机数状态，把 ops 一条条交给规则核心
  3. 只要有一条不合法（钱不够、东西不在、天黑了还想出门）→ 整批不算
  4. 写回时带 house.rev 做条件更新（或用事务）→ 被别的家人抢先改了就重读、重算一次，还不行就退回
  5. 记 ledger，回新的状态和 rev
手机：结果和自己算的一样 → 什么都不做；不一样 → 换成服务器的版本，画面跟着变
```

- 一批里的操作照现在页面的按钮来：`sell`、`deposit`、`buyDoor`、`buyTrap`、`expandYard`、`buyDecor`、`moveDecor`、`startStove`、`collectStove`、`acceptRequest`、`deliver`、`walkTo`、`gather`、`fight`、`flee`、`goHome`、`accompany`、`gift`、`takeDisciple`……每个都直接对应规则核心里已经有的函数（`economy.ts`、`home.ts`、`trade.ts`、`field.ts`、`family.ts`）
- **规则版本**：`RULE_VERSION` 手机和服务器对不上时，提示更新，不收这一批
- 服务器的处理函数**不直接碰数据库**，只拿「读出来的数据 + 一批操作」，返回「要写的数据」。数据库的读写放在外面一层，这样能在本地用内存跑测试，换平台也只换外面那层

### 守夜

1. 天黑点「守夜」→ 服务器建 `nights` 一条：发 `seed`，用 `beginNightLedger` 定好抢夺计划，返回给手机
2. 手机用 `startNight` + `nightStep` 打，**每一步的操作都记下来**（`[步数, 操作]`，操作就是现在的 `NightAction`）
3. 打完交上去 → 服务器用同一个 `seed` 和 `ruleVersion` 从头重放，用重放的结果 `settleNightLedger` 记账
4. 重放和手机报的不一样 → 以重放为准，记一笔可疑日志（不封号，先看看有多少）
5. 打到一半关掉：当天（北京时间 5 点前）回来，从记录接着打；隔天才回来，服务器按 `settleAutoNight` 当交给机关守

**前提**：页面现在的守夜还是自己那一份（和核心逐局对账一样）。上服务器以前，页面要改成直接用核心的 `nightStep`，不然重放会对不上。时间和野外也一样。

### 不在线的夜

- **按房算，不按人算**：一个现实日里，这座房里住的活人都没守过夜，就由机关守一次（`settleAutoNight`，损失上限 `autoLossLimit`）
- 不定时去跑：谁先打开这座房（住在里面的人、来串门的族人、来砸门的厉鬼），服务器就先把欠着的不在线夜补算完（现在 `reconcileAbsence` 的做法），结果写进 `inbox`
- 没有人住的老宅不来鬼

### 当厉鬼

- 服务器挑目标房，把那座房的门和机关拍一张快照存进 `raids`，按快照定 `startHaunt` 的强弱
- 手机打完交操作记录，服务器用 `hauntStep` 重放
- 目标房的损失按第四节第 3 条：建议最多 20 文、不丢宝物，第一世的人家不丢钱（和不在线一样）

### 一座房里几个真人同时在线

- 房的东西都在 `houses` 一条里，靠 `rev` 防止「两个人同时花钱箱」：后到的那批会重算，钱不够就退回，手机提示「钱箱里的钱刚被家里人用了」
- 灶、摆设的位置也一样
- 每个人的天数、钱袋、背包在自己的 `lives` 里，互不影响
- **门破了谁疼（11-28 定）**：输的人自己的钱袋照常被抢两到四成。这座房里还住着别的真人时，钱箱按 `autoLossLimit(chest, 输的人的 lifeNo)` 丢（最多 20 文，第一世的人不丢），不丢宝物；房里只住着他一个真人（别的都是 NPC 或已经走了），照亲手守的规矩 `nightPayout`。用哪种算法在开打时定，和抢多少一起写进 `nights`，打的过程中有人老死或搬走也不变

### 自立门户、搬家

- `foundHouse`：在自己家族里起一座新房，按第四节第 7、8 条分钱、花钱，人搬进去。`houses` 新建一条，`clans.houses` 加上它，原来那座房的 `residents` 去掉他，三处要在一个事务里改完
- `moveIn`：搬进别人的房要先发邀请，那座房里的真人有一个答应就算（异步，进 `inbox`）。`moveOut`：搬回自己以前住过的房，或者起新房
- 背包、钱袋跟着人走；房里的东西（钱箱、仓库、宝物、装饰）留在房里
- 夜里正在打的时候不能搬（等这一夜结算完）

## 九、给 Codex：防作弊

| 怎么作弊 | 怎么防 |
| --- | --- |
| 改手机里的钱、货 | 钱和货只认服务器的 |
| 改守夜结果 | 服务器重放操作记录 |
| 看穿随机数（提前知道野兽打不打得过） | 白天的小事可以接受。**大事的种子只在服务器**：门破了抢多少、禁地会不会丢命、投胎候选 |
| 网络重试多领一次钱 | `opId` 去重 |
| 自己的小号当自己的孩子刷养育分 | 已定的规矩：养育分只算不同真人账号、成年后还在玩的孩子。服务器再看同一台设备、同一个支付账号 |
| 打输了就关游戏 | 已经在「待定」里，等试玩再看 |

## 十、给 Codex：微信那边

- **登录**：云函数里直接拿到 `openid`，不用自己做账号
- **实名和防沉迷**：小游戏由微信的健康系统统一做。「只给成年人玩」要先和微信确认能不能做到、我们能拿到什么（见 ROADMAP「未成年保护」）。服务器这边留一个字段记年龄段，不自己存身份证
- **内容安全**：名字、留话、手绘图案上传前过微信的内容安全接口，不过不让存
- **个人信息**：只存玩游戏要用的；玩家要注销时能整号删掉（祠堂里别人家的画像换成「无名氏」）

## 十一、分几步做

| 步 | 做什么 | 怎么验收 | 花不花钱 |
| --- | --- | --- | --- |
| **S0 本地假服务器** | `src/server/`：每种操作一个处理函数（只用规则核心，不碰数据库）+ 内存里的数据库 + `opId` 去重 + `rev` 冲突重试。页面加一个「连服务器」的存档方式（`assets/loop-storage.js` 旁边），连本地这个假服务器。页面的守夜、时间、野外改成直接用核心 | 单元测试用好几个「假手机」跑：爹妈和陌生人投胎来的孩子住一座房；孩子长大自立门户，钱按分家走，祠堂还是同一个；伴侣各住各的也能生孩子；两个人同时花钱箱只成功一笔；孩子亲手守输了，钱箱最多丢 20 文、不丢宝物，他自己的钱袋照常被抢；网络重试不重复扣；守夜操作记录重放结果一致；改了记录的会被发现；不在线夜按家算、一天只一次；厉鬼砸不在线的家最多丢 20 文。原来的测试照样全过 | 不花 |
| S1 上云 | 同样的处理函数放进云函数，换成云数据库那一层；微信登录；攒天用服务器日期 | 真机两台手机住同一座房，能各玩各的；断网重连不丢账 | 开始花，很少 |
| S2 真人投胎、红线 | 空位、奈何桥挑真人家、新玩家随机分、找有缘人里有真人、红线共用 | 两个账号走完「牵线 → 生孩子 → 孩子是第三个账号」 | |
| S3 真人厉鬼、借好友 | 挑目标、快照、重放；结伴和驰援借好友、族人的快照；好友投奔链接 | 厉鬼砸不在线的房，主人上线看到战报 | |
| S4 运营工具 | 客服查账（`ledger`）、回滚一笔、封号、内容审核后台 | | |

**建议先做 S0**：不花钱，能把「家族和房」「同时花钱」「防作弊」这些最容易出错的地方先在本地测透，也能顺便检验上面「待定」那几条定下来以后好不好写。

## 十二、第一版不做

- 实时一起守夜、白天多人同屏
- 玩家之间买卖、全服统一的行情（行情照旧按 `dayPrices` 每人每天算）
- 野外掉的包别人能捡
- 自由私聊（留话写在祠堂里，过内容安全）
- 换平台（规则核心和数据库那层分开就够了，不提前写第二套）
