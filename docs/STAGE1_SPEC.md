**A1. 一晚只扣一次。**
现在最后一晚（还有护家神那一晚）结算后，`G.phase` 还停在 `night` / `guard`，刷新就从第一波重打，钱和宝物再扣一次。

- 验收：在浏览器测试里加三个用例：普通一晚、最后一晚、护家神一晚，各自在结算页刷新一次。钱、宝物、守住或破门的次数都只变一次，之后能正常走到下一步。

## B. 阶段 1：把时间、野外、五波守夜搬进 `src/core/loop/`

就是 `docs/CODEX_TASKS.md` 任务 2 的第 1、3 项，加上审查报告阶段 1 的要求。

### 范围

| 搬 | 对照样机里的 | 说明 |
| --- | --- | --- |
| 时间 | `CFG`、时辰、天黑、`accrueDays`、`spendDawn`、`BANK_CAP` | 攒天：开局 3 天、每个现实日给 1 天、最多 3 天。「今天是哪一天」由外面传进来（例如 `"2026-11-20"`），核心里**不读现实的钟** |
| 野外 | `RINGS`、`SPOTS`、`renderMap` 里的规则部分、`walkTo`、`gather`、`danger`、`knocked`、`dusk`、`duskChoices`、`goHome` | 三圈、八个地点和线索、采集、独行和结伴、遇险（打 / 跑）、倒下（东西掉在原地；**只有一个人倒在禁地才可能丢命**）、天黑前回家 |
| 五波守夜（亲手守） | `NIGHT`、`GHOSTS`、`TRAPS`、`DOORS`、`PERKS`、`waveCounts`、`startWave`、`spawnGhost`、`hitAt`、`nightStep`、`endNight` 里算输赢的部分 | 鬼的特点、手里的东西、每波挑本事、门、弩机 / 灯笼串 / 镇宅符、邻居驰援、家人帮手、护家神那一晚的加成 |

**这次不搬**：河边那一小片（还在试）、带路、红线 / 孩子 / 徒弟、死后（当厉鬼）、投胎和因果分、卖货和修院子、经营、机关代守（阶段 3）、把页面改成调用核心（阶段 1 验收以后再说）、服务器。

### 要求

1. **新目录 `src/core/loop/`，旧的 `src/core` 文件一个都不动。** 要通过现有的 `npm run typecheck`（核心不能用 DOM、Node、`window`、`process`）。
2. **确定性。** 随机只走注入的随机数（可以复用 `src/core/rng.ts` 的 `Rng`）。不用 `Math.random`、`Date`、`performance.now`。**玩法的随机和长相的随机分开**：换一张脸不能改变战果。
3. **数字照抄样机**，放进一个配置对象，名字和样机的 `CFG`、`NIGHT`、`GHOSTS`、`PERKS` 等对应得上。这次**不调数值**。搬的时候发现样机的规则有毛病，写进汇报，不要顺手改。
4. **守夜是固定步长的模拟**：`nightStep(state, dt, actions)` 这一类形状（名字你定）。玩家操作都是「动作」：点某个鬼、换手里的东西、挑本事、喊邻居。守夜结束时给出一个**结果**：守住还是破门、打散几个、捡到多少、门剩多少，以及按规则该扣多少钱、丢哪件宝物。**结果只算出来，不往存档里写**：「只结算一次」的提交点是阶段 2 的事。
5. **状态是纯数据**（能 `JSON.stringify` 再读回来接着跑），并且把「家」和「人」分开放：家里有门、机关、钱箱、仓库、宝物；人身上有时辰、体力、背包、钱袋、手里的东西。阶段 2 会在这上面加 `houseId / lifeId` 和存档，这次不用做存档迁移。
6. 带一个规则版本号，以后回放和对账要用。

### 测试（都进 `npm test`）

现在 `npm test` 是 `vitest run --dir test`，新测试放在 `test/loop/` 下面就会被跑到。

- **每条规则至少一个单元测试**，包括 `docs/HANDOFF.md` 第 3 节里和这次范围有关的几条：时间只跟着行动走；攒天开局 3、最多 3；倒下掉东西、只有独自倒在禁地才可能丢命；祖传机关第一天照常工作（A3）；每个特点（飞、隐、甲）**至少有三种打法**能守住（用模拟证明）。
- **同种子、同动作，跑两遍结果完全一样**；守到一半把状态存成 JSON 再读回来接着跑，结果和一口气跑完一样。
- **难度对照**：写一个无界面的机器人（每秒 3 或 4 下、按特点换东西、本事随机挑），跑出 `docs/HANDOFF.md` 第 4 节那张表，和 `npm run balance:night` 的结果并排列出来，在合理误差内。样机用的是 `Math.random`，逐局对不上没关系，比的是统计结果；如果你能给样机加一个只在测试里用的固定种子，能逐局对上更好。
- **另做一张「零输入、只靠机关」的表**（不同天数 × 门 × 弩机数量），给阶段 3 的机关代守当参考。只列数字，不要调。审查报告说得对：每秒 3、4 下的胜率不能当成机关代守的胜率。
