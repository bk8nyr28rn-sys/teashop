## 一、存档能留下什么

当前正式样机把一世、一家和账号设置写在同一份 `localStorage['wulin-loop']` 中。刷新同一世通常能回到原地点，带回家的物件也能留下。换一世时，程序根据候选家庭重新创建整份状态。家庭名可以重名，存档中没有能独立寻回原来那户人家的标识。

| 要回答的问题 | 现在的证据 | 建议归属与补充字段 |
|---|---|---|
| 这是谁的家 | 门、三类机关、宝物、普通仓货和祖宗画像都挂在 `G`。回自家时，候选卡复制门、机关、宝物和画像，带回六成钱，普通仓库重新置空 | 家用稳定的 `houseId`。门、机关、家庭钱箱、普通仓、宝物及祠堂挂在家上。候选卡只引用家和所选后人。不同人家分别保存 |
| 谁活完了这一世 | 年龄用本世的 `day` 推算。体力、随身包、位置、伴侣、子徒和本世收入、守夜次数都有记录。`history` 只有往世摘要 | 人用 `lifeId` 引用所在家庭。随身包、体力、结缘和本世功绩跟人；亲属引用稳定人物标识。死亡时按 `lifeId` 给原家的祠堂挂一次画像，后代选哪户都不会重复挂或漏挂 |
| 哪件东西是我摆下的 | 青纹石在院里及其三个摆位可跨世带回自家。河埠的木排、木桥、物件位置、周伯状态则随新一世重建 | 院子的面积、摆件实例及位置、已做成的家用物、在制品和委托归家。河埠公共设施与人物交情分开记录；哪些应跨世保留，须划定范围 |
| 这次回来发生了什么 | `bankedDays / lastGrantDate` 处理现实日赠天。`guideSeen` 是说过的话。河埠 `record` 记走动、搭配和停留。三者都不能回答「昨夜谁守、少了什么、哪件货好了」 | 账号保留攒天、设置、带路记录。家庭事件记 `eventSeq / houseId / nightId / kind / delta`，玩家记 `lastSeenAt / lastReadSeq`。摘要从已提交事件生成；已读只挪游标 |
| 今晚是否已经算过，加工该不该好 | 门的当晚血量、波次和本事在内存 `N`。普通夜结算进入 `dawn`；最后一晚的老死跳转挂在结算按钮上 | 家庭存 `nightId / mode / state / seed / rulesVersion / receipt`、跨世连续的游戏夜序号。工单记 `jobId / houseId / inputs / readyAfterNight / status`。实际过完对应游戏夜即标为可取，次晨展示；领取只能入仓一次 |

## 二、不在线与交给机关守的晚上

**主动托管与离线代守应调用同一个结算函数。** 相同的宅子、来袭、保护状态和余额必须给出相同的门况与损失；“托管／离线”的来源只影响战报措辞。亲自守仍用原有五波、当晚本事和手动破门后果。

1. **先登记来袭。** 保存家庭、来袭标识、对应游戏夜（如有）、有效门级与门血、弩机数量、灯笼串、镇宅符、保护状态、敌人日档、规则版本和随机种子。当前 `waveCounts` 给五波数量，`startWave / spawnGhost` 决定出场及移动。先固定来袭，再选防守方式，刷新读取同一份快照。
2. **只模拟机关。** 在新目录 `src/core/loop/` 提取固定步长的守夜规则。弩机按射程条件和冷却射可见目标，灯笼使近门隐身鬼现形，镇宅符减慢近门移动，门承受攻击。托管不输入点打、换手、家属、驰援、护家神或波间挑本事；清波直接进下一波，直到守住或破门。样机现有 `nightStep` 同时负责这些伤害、SVG 和选本事弹窗，单让页面挂机会得到另一种结果。
3. **按模式一次落账。** 建议自动破门的试算值为下式。手动败局仍按当前规则处理。自动模式只动零钱；人、宝物、普通货、装饰、材料和在制品不损失。不上线不扣因果分，因此自动败局另记，不能递增当前会导致扣分的 `G.broken`。建议主动托管沿用同一待遇。是否计入“亲手守住”的奖励或收徒品级，交产品确认，先分开计数。
4. **把结算放在正确入口。** `renderHome` 的歇到天黑、`afterArrive` 及野外遇暮折返，在开战前提供「亲自守／交给机关」。启动恢复和跨日回前台调用同一个待结算检查。在一次持久化提交中写入钱箱变化、来袭收据、下一相位及到期工单；重复调用只读收据。护家神、厉鬼和最后一晚分别测试。手动结算画面上的按钮只负责继续。

**两个钟的交界需要拍板。** 建议把“现实日的家宅来袭”和“玩家主动过完的游戏夜”分别记账。离开七天时，攒天余额仍最多 3；可以在回访时补出家宅遇袭摘要，一段离线最多扣一次钱。人若离开时还在白天，保留其时辰、随身包和目的地，加工继续等那个游戏夜。若离开时已经交付当晚，则同一来袭合并结算，工单只成熟一次。主动连过三个攒下的游戏日，各有自己的游戏夜。玩家在亲自守到一半退出时，建议同日恢复战斗，跨日如何衔接离线代守由产品确认；已结算的手动损失不再裁算。首日还没装机关也要能托管，在新家保护期内显示实际保护结果。

**回访要能讲人话。** 有事时可显示“昨夜机关守门，少了 2 文；昨晚放下的那批货做好了”，只列确实发生的事项。没有新事件时显示“柴还在仓里，你上回走到河埠”，给继续原事的入口。重复打开可以重看上一条收据，不能再扣钱或再发货。

## 三、经营小样与进入节奏

现有买卖已经有适合接经营的入口。河埠回家会把木头变成仓里的柴，野外背包在进院时入库；集市支持单卖一件、卖完一种和卖完整仓。普通货使用固定价，宝物另存标价。院石可以搬回、选位置，白天和夜里都看得见。扩院、工单、委托和每日变价尚无对应规则。

| 内容 | 在当前代码哪里接 | 最小可验收结果 |
|---|---|---|
| 直接卖与行情 | 把 `storeValue / openMarket / sellGoods / sellAll` 的报价和扣库存共用一处。宝物的 `t.v` 单独保留，是否参与行情待定 | 建议每个游戏日保存一张报价，波幅在基价上下 20% 以内。院里预估、摊上单价、批卖到账一致；刷新不重抽。柴基价仅 3 文，需明确零钱精度与尾数结转，拆卖五次不能比一次卖五件多赚 |
| 加工 | 从家里或集市下单。用家庭仓库存原料、工单存配方与目标游戏夜，夜间收据标记就绪，回院可领成品 | 睡前扣料一次，手动或托管经过同一游戏夜均可完成，次晨能取。现实中过几小时但仍处同一白天，进度不动；双标签领取只有一份 |
| 委托 | 在集市用家庭标识接一份有编号的订单；交付与普通出售、加工共用库存扣减 | 玩家能看到交什么、得什么，可以选择直接卖或留货。交够数量才扣货给钱。重进保留已接单与约定报酬，改日行情不重定旧单 |
| 守门、扩院、装饰、家人四种支出 | 换门装机关沿用 `openBuild`。扩院为家增加实际摆位。装饰复用 `River.placeStone / yardStone` 的三个已有位置、日夜绘制和存档。家人支出可先试一份明确收到的礼物，现有收徒花 30 文、陪伴花时辰 | 用同一笔钱能选择修门、扩位、摆物或花在家人身上，结果次次重进都能认出来。家人收礼与邻居送礼区分；具体物件、价格、关系加成和开放日均为待试参数 |

## 五、将来上服务器会遇到的写法

| 现在的写法 | 将来会遇到的问题 |
|---|---|
| `localDateKey / accrueDays` 看设备当地日期；开页、回前台和定时器都会检查 | 两台设备或不同时区对“今天”的判断可能不同。授天日、来袭日、玩家行动推进的游戏夜需要分别有权威来源 |
| `save` 整份覆写 JSON；跨标签主要合并攒天字段和已说台词；普通保存失败会被吞掉 | 两个客户端同时卖货、交单或买门，后写可能覆盖先前结果。今后要能按家庭版本和操作编号识别冲突、重试和落盘失败 |
