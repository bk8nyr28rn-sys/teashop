# teashop · 融合玩法逻辑核心

《融合玩法方案汇总（v2）》的规则实现和数值模拟器。目前没有画面：这一步只写规则，用来先验证数值。

## 目录

```
src/core/   逻辑核心：只有规则，不依赖任何引擎和 Node API，可以原样放进 Cocos Creator
  config.ts   所有可调数值（对应文档的“待定数值”表），默认值只是占位
  world.ts    世界、家族、时间、闭关
  threads.ts  红线：牵线、互动、剪线、复合、拉黑、冷落、多对象、情丝去向
  grudge.ts   怨丝池和每日上限
  defense.ts  守宅：两种鬼、砸门、感化、失败惩罚、劫后余生、阵法、炼丹
  family.ts   族人和嫡传
  tick.ts     每小时推进一次
src/sim/    数值模拟器（只在开发时用，不进游戏）
test/       单元测试，每条决定至少一个
```

代码注释里的 `#N` 对应 v2 文档“决定记录”的编号。

## 命令

```bash
npm install
npm test            # 单元测试
npm run typecheck   # 类型检查（核心用不含 Node 的配置单独检查）
npm run sim         # 数值模拟：5 类玩家，每类 200 人，30 天
npm run sim -- --players 500 --days 60 --seed 3
npm run sim -- --set grudge.dailyCap=20 --set breach.graceActions=8
npm run sim -- --json
```

## 模拟器里的玩家类型

| 类型 | 假设 |
| --- | --- |
| 独自玩 | 只和 NPC 牵线，每天上线两次 |
| 好友一对一 | 两个专一的好友互相牵线，每天上线两次 |
| 忙碌玩家 | 隔天上线一次，每月闭关 5 天 |
| 多对象（高强度） | 一位真人好友 + 第 3、7、12 天各加一位 NPC，每天上线三次 |
| 多对象（同样投入） | 同上，但上线频率和互动意愿和一对一一样，用来做公平对照 |
| 未成年 | 只在周五到周日 20–21 点能玩 |

这些都是粗略的行为假设，要和真实数据对照着改（`src/sim/agents.ts`）。

## 模拟发现的问题

### 已处理

**1. 多对象原本是最强的玩法。** 一个个关掉机制后发现有两个来源：

- 守门把所有线的浓度加在一起，每根线又各自结族人 → 改成回报递减（第 1 根 100%，第 2 根 50%，第 3 根 25%……），加大心力分散，NPC 线也要维护（回复有延迟、会主动发来互动、不回算冷落）
- 打散和感化怨灵时，还原的情丝比怨丝还多，而且全部流进最浓的线，怨丝成了燃料，多对象第 15 天就到金缕 → 还原比例压到 1:1 以下：打散还原 10%–30%（怨灵越强越多），感化还原 50%

**2. 成长太快，60 天全部到顶。** 按“一对认真的好友约 3 个月到金缕”校准：

| 指标（90 天） | 好友一对一 | 多对象（同样投入） | 独自玩 | 忙碌玩家 |
| --- | --- | --- | --- | --- |
| 金缕中位天 | 89.5 | 未达到 | 未达到 | 未达到 |
| 嫡传中位天 | 24.5 | 44.5 | 不适用 | 未达到 |
| 族人 | 6.3 | 7.4 | 4.9 | 0.2 |
| 砸破/周 | 0.92 | 1.67 | 0.99 | 0.65 |

阵法升级花费改成按等级的平方增长。

### 还没处理

1. **忙碌玩家落后太多**：90 天后单线浓度 23（一对一 197），族人 0.2 个。原因是成长慢，不是怨丝
2. **多对象可能太难了**：同样投入时被砸破的次数是一对一的 1.8 倍
3. **未成年玩家几乎不成长**：一周只能玩一小时，其余时间闭关冻结，90 天后族人 0 个
4. **每日怨丝上限从没触发过**：要在剪线、争执等压力场景里测

“离线期间最多输一次”在所有场景下都成立（#11）。
