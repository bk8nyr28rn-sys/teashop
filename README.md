# teashop · 融合玩法逻辑核心

《融合玩法方案汇总（v2）》的规则实现和数值模拟器。目前没有画面：这一步只写规则，用来先验证数值。

## 目录

```
src/core/   逻辑核心：只有规则，不依赖任何引擎和 Node API，可以原样放进 Cocos Creator
  config.ts   所有可调数值（对应文档的“待定数值”表），默认值只是占位
  world.ts    世界、家族、时间、闭关
  threads.ts  红线：牵线、互动、剪线、复合、拉黑、冷落、多对象、情丝去向
  grudge.ts   怨丝池和每日上限
  defense.ts  守宅：两种鬼、砸门、感化、失败惩罚、劫后余生、阵法、炼丹
  family.ts   族人和嫡传
  tick.ts     每小时推进一次
src/sim/    数值模拟器（只在开发时用，不进游戏）
test/       单元测试，每条决定至少一个
```

代码注释里的 `#N` 对应 v2 文档“决定记录”的编号。

## 命令

```bash
npm install
npm test            # 单元测试
npm run typecheck   # 类型检查（核心用不含 Node 的配置单独检查）
npm run sim         # 数值模拟：5 类玩家，每类 200 人，30 天
npm run sim -- --players 500 --days 60 --seed 3
npm run sim -- --set grudge.dailyCap=20 --set breach.graceActions=8
npm run sim -- --json
```

## 模拟器里的玩家类型

| 类型 | 假设 |
| --- | --- |
| 独自玩 | 只和 NPC 牵线，每天上线两次 |
| 好友一对一 | 两个专一的好友互相牵线，每天上线两次 |
| 忙碌玩家 | 隔天上线一次，每月闭关 5 天 |
| 多对象（高强度） | 一位真人好友 + 第 3、7、12 天各加一位 NPC，每天上线三次 |
| 多对象（同样投入） | 同上，但上线频率和互动意愿和一对一一样，用来做公平对照 |
| 未成年 | 只在周五到周日 20–21 点能玩 |

这些都是粗略的行为假设，要和真实数据对照着改（`src/sim/agents.ts`）。

## 模拟发现的问题

**已处理：多对象原本是最强的玩法。** 一个个关掉机制后发现，原因不是“怨丝变回情丝”，而是两条按线数叠加的规则：守门把所有线的浓度加在一起，每根线又各自结族人。现在三管齐下：

1. 回报递减：守门和结族人都按浓度排序，第 1 根线 100%，第 2 根 50%，第 3 根 25%……（`thread.diminishing`）
2. 心力分散加大：`strainPerExisting` 1 → 3，`reliefPerInteraction` 1 → 0.5
3. NPC 线也要维护：NPC 过 12 小时才回，也会主动发来互动，不回一样算冷落

改完后 30 天、同样投入的对比：多对象被砸破 1.11 次/周，一对一 0.92 次/周；嫡传更慢（0.62 对 1.00）；回报是族人更多（6.4 对 2.8）。高风险高回报，不再是无脑最优。

**还没处理：**

1. **60 天内全部到顶**：浓度 200（金缕）、族人 12、阵法 10 级，成长速度要大幅放慢
2. **忙碌玩家落后很多**：30 天后族人 0 个，原因是成长慢，不是怨丝
3. **每日怨丝上限从没触发过**：要在剪线、争执等压力场景里测
4. 多对象的族人是一对一的 2.3 倍，倍数是否合适要定（调 `thread.diminishing`）

“离线期间最多输一次”在所有场景下都成立（#11）。
